# Hooks and state files

What `cco hook` records and the per-project files below `~/.claude/cco/`.

**Hooks and state files.** `cco hook` (`src/hook.ts`) handles `SessionStart`, `UserPromptSubmit` and `SessionEnd` and writes per-project state files to `~/.claude/cco/<slug>*.json`. It also handles `PreToolUse` (matcher `AskUserQuestion`) and `PermissionRequest`, which only record what the session asks (`recordLocalRequest`, `src/localRequest.ts`: `~/.claude/cco/requests/<session-id>.json` below the session's account, `LocalRequest` with `kind`, `toolName`, `input`, `at`) and print nothing, so they decide nothing and Claude Code asks in its terminal as before; `UserPromptSubmit` and `SessionEnd` remove it, `SessionStart` removes those over a day old. `readLocalRequest` takes it only while it is newer than the transcript's mtime (once answered, Claude Code writes the call and its result); `useLocalRequest` reads it every second while the session's status is `waiting`, and `SessionComposer` shows it read-only (`asked`) in place of the blocked prompt line, in the Remote Control Viewer (whose Enter dialog names it under *Bring its terminal to the front*, `RcViewerSituation.asked`) and the session viewer. The Enter dialog's `steer` (`RcViewerSituation.canSteer`: an idle own-account session without a claude.ai twin, `remoteApi` and `remoteControl` on; never selected first) types `/remote-control` through the local channel; the first time, Claude Code asks once in its terminal (*Enable Remote Control*), and a second `/remote-control` would open its status panel, hence only for sessions without a twin. All of them are written atomically via rename (`writeJson` in `locate.ts`):
- `<slug>.claude-<pid>.json`: the session of one Claude Code process (`CLAUDE_PID`, which Claude Code passes to hooks and commands; `claudePidFromEnv`). Same shape as `<slug>.json`, and `ended: true` on `SessionEnd` (not `clear`) of that process's session. A viewer started with `--claude-pid` (which `cco open` passes) follows only this file and also exits when the pid is gone. Stale files of dead pids are removed on `SessionStart`.
- `<slug>.json`: the project's latest active session, for viewers without a pid (`cco watch` by hand). `ended: true` is set on `SessionEnd`, except when the reason is `clear`, and only if that session is still the active one.
- `<slug>.viewer-<claudePid>.json` (`<slug>.viewer.json` without a pid): pid and current view of the running viewer. `cco open` checks the one of its own Claude Code process and reuses a live viewer instead of opening a second pane. `restore.json` is only rewritten by a session with its own viewer or when no viewer runs in the project, and `SessionStart` reopens only when its process has none (without a pid: when none runs in the project), so a session started from the Sessions view gets its own viewer in its new window.
- `<slug>.restore.json`: whether a viewer was running at `SessionEnd`, and with which view. On `SessionStart` with source `startup` or `resume`, the hook opens the viewer as the `autoOpen` setting says (`remember`: only if this says it was open; `always`: also without it, in the chat; `never`) with `keepFocus`, which sends a `move-focus left` to wt or passes `-d` to tmux. The hook must not print to stdout, because SessionStart output is added to Claude's context. Claude Code writes a prompt to the transcript only after the `UserPromptSubmit` hooks ran, so `cco hook` must start fast: `cli.ts` loads the viewer (`src/watch.ts`: Ink, React, the renderers) with a dynamic `import()` for `cco watch` only, and tsup splits it into its own chunk. Code shared with it lands in another chunk, so `open.ts` starts `dist/cli.js` by name (`CLI`), not its own `import.meta.url`.
- `<slug>.positions.json`: per list (`chat`, `git`, `plan`, `sessions`) the selected entry, whether it followed the newest, whether its copy in the Pinned group was selected (`pinned`, only without follow), and a scroll position per key (turn id, path, `path#file`, plan id, `id#diff`, session id), at most 500 per list (`src/positions.ts`). Views use `usePositions()`, whose `scroll(key, …)` replaces `useScroll`; switching entries must not call `scroll.set(0)`, that would reset the entry being left. Chat and Plan restore the selection once their entries are loaded and store nothing before that. The chat list's selection is kept per session id (`sessions`, at most 500; the list's own fields are the fallback for a session without one and for files written before), and `usePositions` writes only what its viewer changed into what is stored then (`updatePositions`), since session viewers write the same file. A stored selection the shown session does not have (e.g. the new session `/resume` starts in, before it switches) is kept while that session is only followed (`unrestored` in `ChatView`). Its reset effect on `path` runs before the follow effect (deps include `path`): a session continued from other transcripts arrives with all its turns in the same render as the path change, and `last` does not change then.
- `<slug>.views.json`: per session id (at most 500, `src/sessionViews.ts`) the view it was shown in last and the placement chosen for it with `p` (`{ view, placement }`; the first format stored the view as a plain string and is still read). `resolvePlacement` gives the session's placement, else the `placement` setting. With the `rememberView` setting, `App` records it and switches to it when the followed session changes (`/resume`), `cco watch` without `--view` starts in it, and the `SessionStart` hook reopens in it before falling back to `restore.json`'s view. An explicit `--view` (the `/cco:…` commands) wins; `/cco:open` passes `cco open --last-view` instead, which opens a new viewer without `--view` and leaves a running one's view alone (`openPane` with no view and no action).
- `<slug>.control-<claudePid>.json` (`<slug>.control.json`): view-switch requests from `cco open` to the running viewer.
- `<slug>.favorites.json`: marks of the lists (`src/favorites.ts`): `turns` (prompt uuids), `files` (paths), `plans` (tool call ids), `sessions` (session ids) and `days` (Monitor, `YYYY-MM-DD`). The Settings view's marks (`settings`: setting keys and `reset:<id>`; a viewer of one session's in `sessionViewerSettings`) are global like the settings, in `~/.claude/cco/favorites.json` (`globalFavoritesFile`; each file holds only its own lists), and `R` / *Reset settings* clears them (`clearFavorites`). Kept per project, not per session: `--continue`/`/resume` start a new session id but copy the turns with their uuids. The first format (one list per session id) is merged into `turns` on read. Views use it through `useFavorites()`; `markKeys()`/`markFooter()`/`Star` in `layout.tsx` keep Space and Shift+↑/↓ the same everywhere.

The viewer (`src/tui/useViewerControl.ts`) only reacts to changes that happen after it started. It exits when the session ends, after a 1.5 s grace period. Without hooks it falls back to the newest transcript that contains messages; Claude Code also creates tiny bookkeeping `.jsonl` files that must be ignored.
