# Rendering, Git and opening panes

**Rendering.**
- `src/render/markdown.ts` uses `marked` with its own terminal renderer (`terminalRenderer` in `src/render/terminal.ts`; it replaced marked-terminal, which pulled in cli-highlight and its unmaintained dependencies, and keeps its look: `#` headings, `*`/numbered lists indented by two, quotes gray italic, code indented and highlighted, links as `text (url)` or OSC 8 where `supportsHyperlinks`). Its `sgr` styles reopen after a nested close and close at each line end, like chalk. List items render their blocks one by one (a tight item's text has no line break before a nested list); nested lists are indented by their parent's marker width, only the top level by two. Plus:
  - A wrapper that indents the continuation lines of list items.
  - A `table` renderer override (`renderTable`), since `wrapLine` would break table borders apart. Its cells write OSC 8 links out as `text (url)` (`withoutHyperlinks`): `wrapCell` breaks after `/` and `-`, which cut the escape sequence apart and showed the URL as text with wrong widths. Columns keep their natural width if the table fits, else the widest are cut to a common width (`fitColumns`), none below its minimum: its header's longest word and its longest word up to `MIN_COLUMN`, where words also break after `-` and `/` (`pieces`). The text wraps inside the cells (`wrapCell`, which closes styles at each break and reopens them). If the minimums don't fit, the rows are listed as `header: value` lines instead, as Claude Code does. Without wrap (`w`), tables keep their natural width and scroll sideways.
- `src/render/diff.ts` highlights each hunk side as one text, so multi-line comments are colored correctly, and then maps the lines back. Add languages via the `LANGUAGES` map.
- `src/render/highlight.ts` runs highlight.js 11 (all languages; a code block without a language is detected, an unknown one stays plain yellow) and turns its HTML into ANSI (`toAnsi`): each text run takes the style of its innermost scope the theme knows (`title class_` looks up `title.class`, then `title`), so an outer colour continues after a nested token. The truecolor `THEME` (VS Code Dark+, readable on the diff backgrounds) is shared by diffs and chat code blocks and applies styles per line, because highlighted output is split into lines afterwards.

**Git** (`src/git/git.ts`): `readChanges` runs one `git status --porcelain=v2 --branch -z --untracked-files=all` (files and branch together: in a large monorepo each status takes 1–2 s and keeps several cores busy; `all` since every untracked file is listed and diffed, `normal` would give one `dir/` entry) plus `numstat`. It diffs against `HEAD`, or against git's empty tree in repos without commits. Untracked files get a synthetic all-added hunk and are counted manually. `findRepos` (`src/git/repos.ts`, setting `gitNestedRepos`) gives the repositories the view shows: the one around the cwd (`rel` ""), and every folder up to `REPO_DEPTH` (3) below its top level (else below the cwd) with a `.git` folder or file (nested, submodules, worktrees; hidden folders, `node_modules`, `bin`, `obj` skipped), sorted by `rel`. `withoutNested` drops the entries git reports for the repositories below (`tools/bar/` untracked, a submodule's `M`). `GitView` keeps a `RepoState` per root and builds its list with `gitEntries`: per repository its own `repo:<rel>` entry, always, then its files; the entry is drawn as the separator (`ruleText` of `repoLabel`: path or the base's folder name, and branch) and selectable (header, `repoHeader`: operation, branch, upstream, last fetch; preview, `repoLines`: `repoInfoLines`, the changes summed in one line and `recentCommits`, `COMMIT_LIMIT` + 1 read so a dim `older commits: git log` line tells there are more, the heading counting all of them; `readSelectedRepo` reads commits and `repoLive` (FETCH_HEAD's mtime, the stash reflog, `describe`, `rev-list --count`) when selected and with each refresh, the commits, `describe` and the count only when HEAD (`BranchStatus.head`, `branch.oid`) moved or with a search, `repoInfo` (remotes, `user.*`, kind) when selected and with each search, kept with their root so another repository's never show. `src/git/info.ts` reads what it can from the git folder without starting git: `gitDirs` follows a `.git` file and `commondir`, `gitOperation` checks `rebase-merge/`, `MERGE_HEAD` … for every repository with each read, and `RepoState.operation` turns its separator yellow; `Enter` opens the folder; it cannot be marked, and the filter keeps it while its name or one of its files matches). Entry keys (positions, marks) are paths from the base (`fileKey`), so a single repository's are its paths as before. Only while the view is shown (`active`; the Chat view starts no git): the first `REPO_LIMIT` (10) repositories are read with every poll, the rest only after `LOAD_MORE` (until restart) every second (`SLOW_EVERY`), the selected one's always; the search runs on show, `F5` and every sixth poll (`DISCOVER_EVERY`). A poll is planned once the last one is done, `TIMING.gitPoll` (5 s) or `POLL_PAUSE_FACTOR` (3) times its duration later, whichever is longer, so git runs at most a quarter of the time (a 4 s read in a large monorepo ran back to back before, as the interval was shorter); `refresh` never starts a second read while one runs. `pollTimes` (`PollTimes`: a read since `startedAt`, else `lastMs` and `nextAt`) feeds the timer at the right end of the header's rule (`pollTexts`, the first that fits through `rule`'s `right` and `ruleTail`; ticks once a second while shown); `Preview`'s `onRuleClick` gives the click on it, which calls `pollNow` (a read like F5, the next poll planned from its end) unless one runs; F5 waits for a running read and then calls `pollNow` too. Nothing watches files below `.git/`, so git's own writes (index, locks) trigger nothing. `List`'s `render` gets `pinnedCopy`, so a pinned copy can name its repository.

**Opening panes** (`src/open.ts`): `openPane` places the viewer as `right` (`wt -w 0 split-pane -V`, `tmux split-window -h`), `left` (the same plus `; swap-pane left`, because `split-pane` only opens right or below; tmux `-b`) or `window` (`wt -w cco-<claudePid> new-tab`, one named window per Claude Code process; `tmux new-window`). A Windows Terminal window keeps the focus: `move-focus` works only within a window. Don't spawn `wt` with `windowsHide` for a window: Windows Terminal applies the hidden start to the new window, which then exists but never shows. The same holds for `explorer.exe` with a folder (`openInDefaultApp`). `p` in the viewer (`PlacementDialog`) saves the choice for the session and calls `moveViewer`, which starts `cco open --placement … --after-pid <viewer pid>` detached and quits; that waits until the old viewer has gone, so its pane or window has closed and `-w 0` means Claude Code's window again, then opens with `replace` (no reuse of the running viewer). The terminal is Windows Terminal or tmux (`detectTerminal`: `TMUX`, else `WT_SESSION` or `WT_PROFILE_ID`; `WT_SESSION` alone is not reliable, Claude Code can lose it when it restarts itself). Without `WT_SESSION` there is no tab to dock to: `-w 0` (and `-w last`, at least in Windows Terminal 1.12) makes wt create a new window, which `windowsHide` keeps invisible while the viewer runs in it, so `cco open` kept reusing an invisible viewer. That happens after Claude Code restarted itself and for sessions run by the Claude Code daemon (`claude.exe daemon run` → `--bg-pty-host` → the session's `claude.exe`, whose `CLAUDE_PID` is not below any WindowsTerminal process; the tab shows a client process). `openPane` then opens a `window` placement instead (`tabless`) and says so. A `/cco:…` command typed while Claude works waits in Claude Code's queue until the turn ends (slash commands are not absorbed mid-turn, and the `UserPromptSubmit` hook also runs only then), and `split-pane` splits whichever tab is active by then, perhaps another Claude Code's; wt cannot name the calling tab. `cco open` (not with `--after-pid`) therefore checks `openedFromQueue` (`ranFromQueue` in `src/transcript/queue.ts`: the transcript's last `queue-operation` is a `dequeue` under a minute old with no `user` entry after it; Claude Code writes `enqueue` only for queued input and runs the command's `!` line before writing its prompt) and then opens a `window` instead (`away`). tmux targets `TMUX_PANE` (`split-window -t`, `new-window -a -t`). It launches `process.execPath dist/cli.js` directly, because Windows Terminal cannot run npm's `.cmd` shims by bare name.
