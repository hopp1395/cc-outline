# Sessions view

Reading, filtering, the Enter dialog, attaching, starting, deleting, export and import.

- `SessionsView.tsx` reads the transcripts of this project (or, with the `sessionsFolders` setting `other`/`all`, of all) through `SessionIndex` (`src/transcript/sessions.ts`) only while it is visible, every 3 s; the first scan reports partial results. `SessionReader` drops each turn's blocks right after taking the changed files from them, so ~750 MB of transcripts stay at ~70 MB heap. One `SessionReader` per file keeps a byte offset and a `TranscriptParser`, so a rescan only parses what was appended. It adds what the parser ignores: the `/rename` title (`custom-title` entries), `gitBranch`, the time span and the files of `Edit`/`Write`/`MultiEdit`/`NotebookEdit` calls, and `SessionSummary.attachments` (`AttachmentItem`s without data: the turns' pasted images and @-mentions, one per path with the prompts' `uuids`, taken in `summarize`; the images and PDFs of tool results, taken in `consume` from raw lines that contain `"tool_result"` and `"image"`/`"document"`, named through `callLabels`, which `takeBlocks` fills for Read and MCP calls only; `mergeSessions` keeps each once along a chain and numbers them through). `sessionLines` lists them in an `Attachments (n)` section after Plans and fills `rows` (line → attachment) for `Preview`'s `onLineClick`; `o` opens `AttachmentsDialog` with `of="session"`, a trashed session's transcripts mapped through `TrashEntry.items`; the row shows `▣n` (`MEDIA_MARK`, in `SESSION_LEGEND`), the filter's details have their names. Sessions with only slash commands and no changes are left out. The list is sorted, dated and cut to its range by `lastActive` (`sessions.ts`): `SessionSummary.modified`, the transcript's mtime (`IncrementalFile.modified`, from the stat it takes anyway; of a chain the latest), else the last entry; any write counts (Claude working, a notification, a rename, an import or a move), which replaced the earlier rule of the last real prompt; the start only shows in the preview header's span. The details start with a `Transcript` section (`sessionLines`, wrapped by `wrapPath`, before Plans) naming the transcript, the chain's latest (`SessionSummary.path`; in the trash its place there, from `TrashEntry.items`); the header and the dialogs' `sessionHead` do not have it. A session whose `cwd` is gone shows a dim `∅` in the marker's place (not for the active, running or trashed ones), its project name struck through with all projects, `folder gone: …` in the header and `folder gone` in the filter's details; `folderGone` looks each folder up once (a ref cleared by F5), while `situationOf` checks live. Which sessions run in a Claude Code (`runningSessions` in `trash.ts`: `~/.claude/sessions/<pid>.json` with a live pid) and what Claude does there (its `status`: `busy`, `waiting` for a permission or question, `idle`; missing before 2.1.283) is read every second while the view is shown (`useRunning`); `SessionMarker` blinks the list's `●`/`▶` bright and dim while `busy` and yellow on and off while `waiting` (`useBlinkOff`, phase from the clock), and the header names both.
- Sessions filter (`a`, `SessionFilterDialog`, `src/sessionFilter.ts`): three settings replaced `sessionsScope` (`readSettings` maps its four values, and `allProjects` before it, through `LEGACY_SCOPES`): `sessionsFolders` (`this`/`other`/`all`), `sessionsAccounts` (`current`, `all`, which also takes accounts signed in later, or config folders joined by `|`, `isAccountsSetting`) and `sessionsBackground` (`show`/`hide`). `sessionFilter` turns them into a `SessionFilter` among the accounts found (a list naming none found falls back to this one), `filterSettings` back. The dialog has check boxes per group (folders, accounts with two or more, left out in the trash; background and remote as one box each under *Others*, `show`/`hide`; their former value `only` reads as `show`, keeps the last box of a group checked and applies on `Enter`; the three Settings rows (`dialog: "sessions"`, the list value shown by `ownName`) open it too. `passesFilter` runs on the read sessions (the active one always passes) and on the trash (folders and background only; `X` purges the entries shown, not the whole scope); the own folder is always scanned, only this project's while its account is unchecked, so the active session is there. `filterIsSet` lights `a filter` in the help line. Background sessions: `SessionReader` sets `SessionSummary.background` from `entrypoint: "sdk-cli"` (`claude -p`, SDK: `sdk`) or `sessionKind: "bg"` (`daemon`, also for a session sent to the background later); `backgroundOf` also counts a running `kind: "bg"`. Every mark of the list is in `SESSION_LEGEND` (`src/tui/legend.ts`): the dialog packs them in short (`legendLines`), the Settings rows with `legend` list them in full. `LEGENDS` there holds the marks of every view's list in short (`ShortMark`; Sessions: `SESSION_LEGEND` and `↓ more ↓`), which the info dialog (`i`) shows on its second page, `Legend` (`InfoPage`; `←`/`→`/`Tab` in `App` switch, it opens on `Keys`); a new mark in a list needs an entry there. The row shows a dim `◌` before the project name and title, the header `backgroundLine` (`claude attach <jobId>` while the daemon runs it), the filter's details `background …`.

- Session dialogs share one head (`src/tui/sessionHead.ts`): `sessionHead(s, ctx, { dir, gone, state })` gives title, span · prompts · files, the account line (`accountLine`: `accountBar` in `barColorOfAccount`, only with two or more accounts), the folder and where it stands (`HeadState`, `{ trash }` for the trash); `countHead` stands in for several sessions. Sessions (`headFor`), `useAccountFlow` (`headOf`; the account menu, *What to do in <email>?*, puts the account's lines above it) and `RenameDialog` (`lines`) use it. `ChoiceDialog` drops the detail rows of the options not selected when the dialog would be taller than the pane. Labels say where it goes on: *Continue it in this Claude Code*, *Continue it in a new Claude Code window* (`SessionSituation.account` names the account in the detail), *… and attach*, *Continue it in <email>…* (one other account; else *another account…*), the same in the account menu.
- Attaching (pairing): every viewer gets `onPair` from `App`; the dialog's `attach` on a session in `running` whose process has no viewer (`attachBlocked`: `runningViewer(s.cwd, pid)`) calls `pairViewer` (`src/viewer.ts`) moves the registration to `viewer-<pid>.json` (so `/cco:…` of that process finds it; `unregisterCurrentViewer` removes the latest one on exit) and writes `claude-<pid>.json` if the hooks have not, and `Viewer` in `watch.ts` remounts `App` (key `cwd#pid`) with that cwd and pid in the chat, in the same pane; an attached viewer thereby leaves its former process. `detach` (`detachViewer`) moves the registration back to `<slug>.viewer.json` and `Viewer` remounts without a pid, in Sessions. One viewer per Claude Code: `cco watch --claude-pid` exits when `runningViewer` names another live one.
- `Enter` in Sessions always opens a `ChoiceDialog` (`src/tui/ChoiceDialog.tsx`: ↑↓ past disabled options, Enter, digits, Esc; it closes on a choice) with the options of `sessionOptions` (`src/tui/resumeChoice.ts`) for the session's `SessionSituation` (`situationOf`): `current` (a paired viewer's own session: `stay` first, `detach`), `active` (runs in a Claude Code: paired `switch` first then `attach`, detached `attach` first then `switch`) or `inactive`; each list ends with `rename`, `export` (`Export it`, or `Export N marked sessions` while some are marked: `SessionSituation.marked`), `import` and `copy` (`claude --resume`, or `claude attach <jobId>` for a daemon session), `copy` selected when nothing else can be chosen (no terminal, folder gone). An inactive session whose folder is gone and whose slug differs from the viewer's (`movable`) gets `move` first and selected (`↵ move to this project`): after a `ConfirmDialog`, `moveSession` (`src/export/move.ts`) writes its transcripts and their folders (`<id>.jsonl`, `<id>/` of every id of the chain) into the viewer's project, rewritten like an import (ids kept), removes the old ones (and the slug folder if empty), and moves cco's marks, positions and view (`sessionCcoData`, then `removeFavorite`/`forgetScroll`/`forgetSessionView` in the old project); `file-history`/`session-env` stay. With no session at all (`sessions` empty, not while a filter hides them), the list gets an `IMPORT_ENTRY` above `↓ more ↓` (`⤓ import sessions…`, `ImportRow`; Enter or a double click opens the import, `↵ import`). `rename` opens `RenameDialog` (the `/rename` title filled in; empty refused, unchanged writes nothing) and `renameSession` (`src/transcript/rename.ts`) appends a `custom-title` entry to `SessionSummary.path`, the chain's latest transcript; only for `inactive` sessions, since a running Claude Code writes its own title again. `enterLabel` gives the help line (`↵ detach…` for `current`). For an inactive session, a viewer with a Claude Code (`paired` from `App`: `claudePid`, no `--session`) offers `here` (first when `isEmptySession`: no turn but a `/clear` at the start; disabled while its `~/.claude/sessions` status is `busy`/`waiting`, and for a session whose `projectSlug` differs from the viewer's cwd, `otherFolder`: `/resume` only lists the sessions of Claude Code's own folder) and `window` (no `window-attach`: the new Claude Code's hook opens a viewer of its own, and this one stays with its Claude Code). `here` (`resumeHereMethod`): `resumeInClaude` types `C-l` (Claude Code's `chat:clearInput`), `/resume <id>` and, a moment later, Enter: in tmux into its pane (`send-keys`), on Windows into its console (`CONSOLE_INPUT_SCRIPT`: PowerShell `FreeConsole`, `AttachConsole(claudePid)`, `WriteConsoleInputW` on `CONIN$` with 20-byte INPUT_RECORDs; ConPTY hands the key events to the raw-mode reader whatever has the focus). The kernel32 calls are declared through Reflection.Emit (`DefinePInvokeMethod`, ~70 ms): `Add-Type` compiled the same C# in ~10 s. PowerShell itself takes about a second to start, so the dialog starts it when it offers `here` (`prepareConsoleInput`, a `ConsoleTyper` that reads the text on stdin); choosing `here` hands it on, anything else and closing the dialog `cancel` it. If that fails (or elsewhere) it copies the command and `focusClaudePane` sends `wt -w 0 move-focus` towards Claude Code (placement right/left only). A viewer without one offers `window-attach` (first) and `window`. `window-attach` writes `<slug>.pairing.json` (`requestPairing`: session id, `until`), which the SessionStart hook uses up (`takePairing`) instead of opening a viewer, starts the session with `resumeForPairing` (wt window named `pairingWindow(id)`, tmux `new-window -P` for the pane id), polls `runningSessions()` for the id every 500 ms up to `PAIR_TIMEOUT_MS` and then calls `onPairStarted`: `App` writes the target's `claude-<pid>.json` (`writeTargetSession`) and `moveViewer(…, target)`, whose `cco open --target` splits that wt window (`-w <name>`) or tmux pane instead of the calling one. Timeout or Esc withdraws the request (`cancelPairing`); the started Claude Code keeps running.
- The `window` and `window-attach` options start the session with `resumeInNewWindow` (`src/open.ts`): `wt -w new new-tab -d <cwd> node cli.js claude --config-dir <claudeDir()> -- --resume <id>`, a window of its own (`-w new`: without it wt may add a tab to an open window; no `windowsHide`, see Opening panes; `cco claude` (`runClaudeIn`, `src/launch.ts`) runs claude through the shell, which finds both claude.exe and an npm .cmd shim, under that config folder (on Windows as one quoted command line, `claudeCommandLine`: an argument list with `shell: true` makes Node warn, DEP0190), then an interactive shell, which keeps the window open (`shellAfter`: `cmd /k`, without cmd's banner)), or `tmux new-window` with `exec $SHELL` afterwards. The active session is refused; for one running in another Claude Code, `Enter` (`↵ switch`, its own confirmation) calls `switchToSession` (`src/switchSession.ts`) with the `RunningSession` from `~/.claude/sessions/<pid>.json`: in tmux the pane of the process or an ancestor (`tmux list-panes -a`, `ps -o ppid=`), selected with its window and session; on Windows the Windows Terminal tab whose title (Claude Code's, without its ✳/◐/◑ mark) is the session's `name` or `/rename` title, found and selected through UI Automation in PowerShell (`TAB_SCRIPT`, `-EncodedCommand`, titles in `CCO_TAB_TITLES`; about 1–2 s), only if exactly one matches; a daemon session (`kind: bg`) without a tab is named with `claude attach <jobId>`.
- Deleting (`src/transcript/trash.ts`) works on the session's own project folder (from `SessionSummary.path`, not the viewer's cwd) and moves its parts (`projects/<slug>/<id>.jsonl`, `projects/<slug>/<id>/`, `file-history/<id>/`, `session-env/<id>/`) to `~/.claude/cco/trash/<slug>/<id>/` under their path relative to `~/.claude`, with a `manifest.json` (items, deletion time, the `SessionSummary` for display). Restore moves them back and refuses if a path exists again; purge removes the trash folder and the mark. The active session and sessions with a live pid in `~/.claude/sessions/<pid>.json` are refused. `ConfirmDialog` (on the shared `Dialog` frame in `layout.tsx`) asks first (Enter yes, Esc no); while it is open, `App` ignores its own keys (`onModal`).
- Export (`src/export/`; the `export` option of the Enter dialog: the marked sessions, else the selected one; there are no keys for export and import): `ExportDialog` (a form, ↑↓ field, ←→/Space value, filled by `readExportOptions` from `~/.claude/cco/export.json`, the first time with `showTools`/`showThinking`; `saveExportOptions` on Enter) then `exportSessions` (`archive.ts`) writes one zip into `downloadsDir()` (`CCO_EXPORT_DIR`, else `~/Downloads`, else home) as `cco-session-export.zip`, or ` (2)` … (`freeName`), first under `.part`. Per session and format a folder `<YYYY-MM-DD-HHMM>-<id8>-<format>` (`sessionFolder`, local time of `lastActive`), all four always (`EXPORT_FORMATS`): `markdown` and `llm` (`sessionMarkdown`), `json` (`sessionJson`, `JSON_SCHEMA_VERSION`) and `backup`. `loadSession` reads the chain (`continues` + `path`) with one dedupe parser like `useTranscript`; `boxesAsQuotes` (`markdown.ts`) turns the frames into quotes; `ImageSource` reads each transcript once for prompt images (by uuid) and the images and PDFs of tool results (by `tool_use_id`), preferring the saved copies, into `attachments/` (`turn-NNN-image-i` pasted, `-shot-n` browser, `-tool-image-n`, `-pdf-n`; Markdown shows images and links PDFs, JSON lists `screenshots` and `pdfs` per tool block); with *whole conversations* each subagent (`loadSubagent`) becomes `agents/<type>-<agentId>.md`/`.json`. The backup holds `claude/<path relative to ~/.claude>` for `sessionItems` of every id plus the `uploads/` images the turns name (`backupFiles`), `manifest.json` (`BackupManifest`) and `cco.json` (`sessionCcoData`: marks, scroll positions, view, placement of its turns, plans and ids). `zip.ts` is a small writer/reader of its own (store/deflate, CRC-32, UTF-8 names, no zip64), no dependency. The run shows in the progress dialog (`exportProgress`: the format per session as the step, the session in the detail line), at the end with the archive's path. The `import` option (or the empty list's entry) opens `ImportDialog` with `newestExport()` and the target (`into`), and `importArchive(file, cwd)` (also `cco import <zip>` with `process.cwd()`, loaded dynamically) imports into the viewer's project folder, not the one the session came from. `src/export/relocate.ts` builds a `Relocation` (`from`: `manifest.cwd`, else the transcript's first `cwd`; `claudeFrom`: `manifest.claudeDir`, written since this version; the slugs; `ids`): `relocatePath` puts files below the new slug and ids, and `relocateText` rewrites the text files below `projects/` (`rewrites`: `.jsonl`/`.json`/`.txt`/`.md`; file history and session env are copied as they are) and `cco.json`: ~/.claude first, then the folder (each behind a placeholder, so a project in the home folder does not catch ~/.claude), in each spelling (`spellings`: Windows with `\`, escaped once or twice, or `/`, case-insensitive; Git Bash `/c/…`; POSIX), whole parts only, into the same spelling of the target; then the slug after `projects` and the ids. A session with an id of its chain in the target folder is skipped (`already there`); one whose ids are in another folder gets new UUIDs for the whole chain (`freshIds`, `ImportResult.imported[].from`), and a copy imported before is found by the first entry's uuid (`holdsCopy`) and skipped too. It refuses paths out of `~/.claude`, keeps existing files (shared uploads) and merges `cco.json` into the target (`mergeCcoData`, nothing overwritten); the view then selects the first imported session, whose fresh mtime puts it on top. `export.json` is one of doctor's `GLOBAL_FILES`.
