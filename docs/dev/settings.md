# Settings

Global settings, the settings of session viewers.

Settings are global rather than per project: `~/.claude/cco/settings.json` (`src/settings.ts`), with defaults in `DEFAULT_SETTINGS`; `readSettings()` falls back to the default for values of the wrong type or, for `autoOpen`, unknown ones. Views use them through `useSetting()`, which writes on every change; `updateSettings()` notifies `subscribeSettings()` listeners and `useSetting` reads a cached copy through `useSyncExternalStore`, so a change in the Settings view (or `t` in Chat) shows in every view at once. `SettingsView.tsx` builds its list and details from `SETTING_ROWS`; a new setting needs an entry there (a test checks that every key of `DEFAULT_SETTINGS` has one). Its description says when to pick which value, and each value's meaning carries an example where one helps; description, meanings and notes may be functions of a `TextContext` (today, the project's cwd, `detectTerminal()`), so the examples show today's dates, this project's files and the keys of the terminal in use, and a note that comes out empty is left out (`settingLines`). A row with `look` draws such values as they look, one line each without a meaning (the account colours: the name on its colour, `colorBadge`). What one types (keys, gestures with a key, `/` commands, shell commands and flags, paths, filter input) is written in backticks in these texts and in the Reset and update entries' details; `wrapText`/`codeMarks` show it yellow like the chat's inline code (`codeSpan` of `render/terminal.ts`), dimmed within notes, and the filter searches it without them (`plainMarks`). Values and screen texts are not marked, nor a command's output; a test checks that the backticks pair up and none is shown. The rows are ordered by group, and `List` with `group` puts a separator above each (Start, General, one per view: `tab` first via `viewTab`, `order` last via `listOrder`; Settings with only its list width; then Reset and Releases). A row is the label with the value right-aligned (`shortValueName`: `newest`/`oldest` for the order values); a label too long for the rest is cut, not the value. The Settings view's Reset entries (`RESET_ACTIONS`) reset all settings, delete the project's data files (`src/projectData.ts`: favorites, positions, views, restore; not the hook state), or restart the viewer (`onRestart` → `moveViewer` without `updatedTo`, none with `--session`). `App.resetProjectData` pauses position writes (`suspendPositionWrites`, since unmounting views would save theirs again), deletes the files and remounts all views through a `Fragment` key. `confirmQuit` is read in `App` and in `SettingsView` (off: the Reset entry *restart the viewer* asks nothing and calls `onRestart` at once; `/cco:restart` never asks), `marquee` in `EntryText`, `dateSeparators` in `List`, `rememberPositions` in `usePositions` (off: neither read nor written). The view settings (`viewChat` … `viewMonitor`, `VIEW_SETTINGS`) hide tabs: `Tabs` skips a hidden view unless it is the open one, `App` ignores its number key, and `shownView` replaces a remembered view that is hidden (App start, `/resume`, the SessionStart hook); an explicit `--view` still opens it. Settings has no such setting, and `isLastView` keeps one other view shown.

Session viewer settings: a viewer of one session (`setSessionViewer(true)` in `watch.ts`, `isSessionViewer()`) keeps `SESSION_VIEWER_KEYS` (chat display, compact layout, mouse, marquee, date separators, pinned favorites, filter in, confirm quit, remember positions, the chat's and Settings' list widths) apart from the project's viewer in `settings.session-viewer.json` next to `settings.json` (`sessionViewerSettingsFile`, shared by all such viewers of the config folder). `readSettings` then returns `readMainSettings()` with that file's part over it (`readSessionViewerSettings`, each value checked like settings.json's by `validated`); the first such viewer finds no file and writes the main values' part (`sessionViewerPart`), and from then on nothing goes across. `updateSettings` writes its keys to that file and only the rest to settings.json; `resetSessionViewerSettings` (`defaults` or `main`) backs the Reset group of its Settings view (`SettingsView` with `oneSession`, from `isSessionViewer()`, not `fixed`: tests render `App` with `sessionId` for the normal views; `settingsEntries(…, true)`: those rows and `SESSION_RESET_ACTIONS`, no Account, Releases, doctor or restart). `useSetting` keys its cache by `ownSettingsFile()`. `App` does not offer the update there (`fixed`). The doctor checks the file like settings.json (`settingsFileCheck`; a key outside `SESSION_VIEWER_KEYS` is unknown there). `usageLine` is in `SESSION_VIEWER_KEYS` and `RC_VIEWER_KEYS` but means nothing to the project's viewer (it has no prompt line), so `isViewerOnlyKey` keeps its `SETTING_ROWS` entry out of the project viewer's list (`listedRows(false)`).
